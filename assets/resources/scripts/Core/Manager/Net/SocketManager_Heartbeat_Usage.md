# SocketManager 心跳机制使用说明

## 功能概述

SocketManager 现在内置了 WebSocket 心跳机制，用于防止连接频繁断线。心跳机制会自动检测连接状态，在连接异常时触发重连。

## 主要特性

1. **自动心跳发送**: 定期发送心跳包保持连接活跃
2. **心跳响应检测**: 检测服务器心跳响应，超时则触发重连
3. **智能重连**: 心跳超时时自动触发重连流程
4. **可配置参数**: 支持自定义心跳间隔和超时时间
5. **开关控制**: 可以动态启用/禁用心跳机制

## 配置参数

- `_heartbeatInterval`: 心跳发送间隔，默认30秒
- `_heartbeatTimeout`: 心跳响应超时时间，默认10秒
- `_isHeartbeatEnabled`: 是否启用心跳机制，默认true

## 使用方法

### 1. 基本使用

心跳机制会在 WebSocket 连接建立后自动启动，无需额外配置。

```typescript
// 连接 WebSocket
await SocketManager.getInstance().initSocket('ws://your-server.com');

// 心跳机制会自动启动
```

### 2. 自定义心跳配置

```typescript
// 设置心跳间隔为20秒，超时时间为5秒
SocketManager.getInstance().setHeartbeatConfig(20, 5);
```

### 3. 控制心跳开关

```typescript
// 禁用心跳机制
SocketManager.getInstance().setHeartbeatEnabled(false);

// 启用心跳机制
SocketManager.getInstance().setHeartbeatEnabled(true);
```

## 心跳数据格式

### 发送的心跳包
```json
{
    "action": "heartbeat",
    "uid": "1640995200000",
    "timestamp": 1640995200000
}
```

### 服务器响应格式
服务器应该返回以下格式的响应：
```json
{
    "action": "heartbeat_response",
    "uid": "1640995200000",
    "timestamp": 1640995200000
}
```

## 工作流程

1. **连接建立**: WebSocket 连接成功后自动启动心跳机制
2. **定期发送**: 每隔指定间隔发送心跳包
3. **响应检测**: 发送心跳包后启动超时检测
4. **超时处理**: 如果超时未收到响应，触发重连流程
5. **连接关闭**: 连接关闭时自动停止心跳机制

## 日志输出

心跳机制会输出详细的日志信息：

- `心跳机制已启动，间隔: 30秒`
- `发送心跳包: {"action":"heartbeat","uid":"1640995200000","timestamp":1640995200000}`
- `收到心跳响应`
- `心跳响应超时，准备重连`
- `心跳机制已停止`

## 注意事项

1. 心跳机制与现有的重连机制完全兼容
2. 心跳超时会自动触发重连流程
3. 重连成功后心跳机制会自动重新启动
4. 建议根据网络环境调整心跳间隔和超时时间
5. 服务器需要支持心跳响应才能正常工作

## 最佳实践

1. **网络环境良好**: 心跳间隔30秒，超时10秒
2. **网络环境较差**: 心跳间隔15秒，超时5秒
3. **移动网络**: 心跳间隔20秒，超时8秒
4. **测试环境**: 心跳间隔10秒，超时3秒

## 故障排除

如果心跳机制不工作，请检查：

1. 服务器是否支持心跳响应
2. 网络连接是否稳定
3. 心跳配置是否合理
4. 查看控制台日志输出
